# Step 3 – 几何 / 干涉推理（Geometric & Interference Reasoning）

---

## 1. 步骤定义与成功标准

**定义**

几何 / 干涉推理 =  
在已建好的零件或子装配基础上，对几何关系进行机器化理解与判断，包括：

- 基本几何属性：尺寸、角度、边数、形状类别（圆柱、L 型块、法兰等）。
- 空间关系：上下、左右、前后、内外、相切/相交等。
- 干涉 / 碰撞：两零件是否占据同一体积；间隙是否满足约束（≥ 指定间隙）。
- 约束一致性：尺寸标注、装配约束、接触面是否自洽。

**成功标准**

一个在该步骤表现“合格”的 LLM / Agent，应能做到：

1. 在给定 CAD 模型（或其程序 / B-Rep / 网格）的情况下，准确回答几何问答：
   - 如 “这是什么基本几何体？主躯干是圆柱还是立方体？”、“有几个孔？”、“三角形是等边/等腰/不等边？”  
2. 对给定的两个（或多个）零件，能判定是否发生体积重叠（碰撞 / 干涉），并给出：
   - 是否干涉（布尔值）
   - 干涉体积 / 接触区域位置（如可从几何核中读取）  
3. 能基于自然语言描述理解空间关系：
   - 如 “在左侧板上、矩形上方钻孔”，“在中央再加一个小矩形体”等，并在 CAD 表示中定位对应区域（SCOPE 的目标）

## 2. 具体案例示例

**案例：法兰 + 轴装配中的干涉检查**

- 输入：
  - 一个法兰零件（带 4 个螺栓孔和中央通孔）
  - 一个轴零件（带肩部台阶）
  - 设计约束：轴肩部应与法兰平面贴合，轴直径应略小于法兰中心孔直径，确保有 0.02 mm 间隙，且轴肩不与法兰倒角干涉。
- Agent 任务：
  1. 从 CAD 模型中读取或推断：
     - 轴直径 d_shaft
     - 法兰中心孔直径 d_hole
     - 接触区域附近的倒角尺寸
  2. 通过几何核（如 FreeCAD/OCCT 布尔运算）计算：
     - 两个实体的交集体积 V_common（使用 Part.Shape.Common）  
  3. 输出结论：
     - 若 V_common > 0 且交集不只局限在设计接触面 → 判定为“干涉”
     - 同时给出干涉区域的坐标 / 面 ID，以及建议修改（如减小轴肩直径或倒角半径）

**成功表现**

- Agent 给出的判定与人工使用 CAD 软件自带的“碰撞检测 / 布尔交集”结果一致；
- 在多轮对话中，能解释“干涉发生在哪里”和“如何修改”而不自相矛盾。

## 3. 专业模型 / 软件（优先开源）

### 3.1 FreeCAD + OCCT / PythonOCC

- **是否开源**：是（LGPL / LGPL 相容开源）
- **链接**：  
  - FreeCAD 官方站点：https://www.freecad.org  
  - FreeCAD 文档（布尔运算示例）：  
  - 研究中对 FreeCAD 碰撞检测的使用（Part.Shape.Common）：  

**主要功能（与几何 / 干涉相关）**

- 基于 Open Cascade Technology (OCCT) 的 B-Rep 几何内核；
- 提供布尔运算：并集（Fuse）、差集（Cut）、交集（Common）；
- 可通过 `Shape.Common(other_shape)` 获得两实体的交集体积，实现碰撞 / 干涉检测；
- Python 接口（含 PythonOCC）可脚本化调用，用于自动化测试。

**典型输入 / 输出**

- 输入：
  - 两个或多个 `Part.Shape` / `Part.Solid` 对象（来自零件或装配）
- 输出：
  - 布尔交集对象（若体积 > 0，即产生干涉）
  - 体积、质心、包围盒等几何属性

> 你可以直接在 FreeCAD Python 控制台中将这些操作封装成 Tool，提供给 LLM/Agent 调用，用于“几何问答 + 干涉检测”反馈。

---

### 3.2 CAD-Assistant（Tool-Augmented VLLM for CAD）

- **是否开源**：代码公开，但采用 **Attribution-NonCommercial License（非商业许可）**  
- **项目页**：https://cadassistant.github.io   
- **代码仓库**：https://github.com/dimitrismallis/CAD-Assistant   

**主要功能（与几何 / 干涉相关）**

- 使用 VLLM（如 GPT-4o）作为 planner，通过 FreeCAD 工具链执行 CAD 操作；
- 内置 `solid_recognizer` 工具，可对 3D CAD 模型进行渲染并输出 JSON 形式的几何参数，用于回答如下问题：  
  - 主体形状是圆柱/立方体/L 型块？  
  - 法兰上孔的数量、分布是否满足条件？  
- 支持 2D/3D CAD question answering（使用 SGP-Bench 的 2D/3D CAD 子集），包括形状分类、角度数量、孔数等  

**典型输入 / 输出**

- 输入：
  - FreeCAD `.FCStd` 文件（2D 草图或 3D 实体）
  - 自然语言问题（通常为多选题），例如：
    - “给定 3D CAD 模型，主体几何形状是什么？A) Cylinder B) Sphere C) L-shape D) Cube”  
- 输出：
  - 规划好的工具调用序列（如调用 `solid_recognizer`、解析 JSON）
  - 最终答案（如 “C) L-shape, TERMINATE”）

> 虽然它没有专门的“碰撞检测工具”，但其框架非常适合作为“几何 / 干涉推理 Agent”的范例——你可以在其工具体系中加入 FreeCAD 的布尔交集 / 碰撞检测 Tool。

### 3.3 CAD-MLLM / Omni-CAD（几何理解的上游资源）

- **是否开源**：论文 + 数据集描述公开；代码 / 模型部分组件开源，整体框架部分仍在逐步开放中。  
- **CAD-MLLM 论文**：介绍了统一的多模态 CAD 生成框架（支持文本 / 图像 / 点云到 CAD）  

**与本步骤的相关性**

- Omni-CAD 数据集提供大规模命令序列 + 多视图图像 + 文本描述，可作为几何理解 & 形状分类的预训练数据来源；
- 这些多模态信号可以帮助 Agent 学会“看到形状就知道是法兰 / 轴 / 支架”等，从而为后续干涉推理提供语义先验。

## 4. 评测环境（执行 / 验证几何 & 干涉）

1. **FreeCAD + 自定义碰撞检测脚本（推荐）**

   - 通过 Python 脚本调用：
     - `shape1.Common(shape2)` 来求交集；若体积 > 0，则判定为干涉  
   - 可将每个装配场景封装成固定测试脚本，记录“是否应干涉”的 ground truth，用于自动评估 Agent。

2. **FreeCAD 宏 / 插件级碰撞检测**

   - 社区已有基于 FreeCAD 的 Collision / Interference Checker 宏，可作为人工校验或 GUI 辅助工具  

3. **CAD-Assistant 评测脚本（几何问答侧）**

   - CAD-Assistant 仓库中提供 `run_cad_evaluation.py`，基于 SGP-Bench 的 2D/3D CAD QA 进行评测，对 VLLM + 工具引导能力进行打分  
   - 你可以复用其 FreeCAD 环境和 `.FCStd` 文件，只替换为自己的 Agent / Planner。

4. **底层几何核：OCCT / PythonOCC**

   - 在不依赖 FreeCAD GUI 的情况下，可直接使用 OpenCascade / PythonOCC 进行高性能布尔运算和碰撞检测；
   - 适合做大规模自动化测试（如批量装配干涉扫描）。

## 5. 若要训练 Agent：可用的开源 / 公开数据集

> 这里重点是“可支持几何 / 空间推理”的数据，而非都已经带有“干涉标签”。很多数据可以通过你自己的几何核后处理，自动生成干涉标签。

### 5.1 SGP-Bench（CAD 子集）

- **是否开源**：是  
- **链接**：https://sgp-bench.github.io   

**数据内容**

- 提供两类符号图形程序：SVG（2D 矢量）和 CAD（2D/3D 对象）；
- 每个示例包含：
  - 程序（如 CAD 命令序列 / DSL）
  - 对应渲染图像
  - 多个选择题形式的问题 & 答案，关注几何属性和拓扑结构  

**具体样例**

- 样例问题（在 CAD-Assistant 的附录中）：
  - “给定一个 2D 草图，问三角形是什么类型？A) 等边 B) 等腰 C) 不等边 D) 直角”  
- Agent 需要从 CAD 程序或几何参数中计算边长，推断类型。

**你可以如何用它来训练几何 / 干涉 Agent**

- 作为“几何理解”基础预训练集，让模型学会：
  - 多边形类型识别
  - 孔 / 特征计数
  - 组合几何体识别（L 型 / 十字形 / 带凸台块等）
- 后续可以在此基础上加入你自己的“装配 + 干涉”合成数据。

---

### 5.2 SCOPE 数据集（三元组：原 CAD + 空间约束指令 + 编辑后 CAD）

- **是否开源**：论文中声明为“开放数据集”，具体发布多在论文 / 项目页附带文件中，需要关注项目后续更新  

**数据内容（根据论文描述）**

- 每条数据由三元组构成：
  - 原始 CAD 序列 `C_main`
  - 空间约束自然语言指令 `I`（包含 “左侧 / 上方 / 中央 / 内部”等空间词汇）
  - 编辑后的 CAD 序列 `C_edit`；
- 通过自动数据生成管线，构造大量“空间约束编辑”样本，如：
  - “在现有矩形左侧上方添加一个长方体凸台”
  - “在圆孔右侧再钻一个孔”  

**具体样例（论文中示意）**

- 输入：原 CAD 序列 + 文本 “Add a smaller central rectangular prism”
- 模型通过 locate-then-infill 策略找到“中央位置”的 token 区间，并替换（infill）为新的 CAD 操作序列  

**与干涉推理的关系**

- SCOPE 专注于“空间定位 + 编辑”，虽然没有直接给干涉标签，但：
  - 你可以利用其三元组，在编辑后用几何核检测是否有不合理的干涉；
  - 或者将其作为训练模型理解“上方 / 左侧 / 中央 / 相邻于”等空间词汇的语料。

---

### 5.3 Omni-CAD / mmABC 等多模态 CAD 数据集

- **是否开源**：数据集描述公开，部分数据与代码可通过论文提供的链接获取；多为学术用途许可  

**数据内容**

- Omni-CAD：
  - 基于 ABC B-Rep 数据集，构建 453,220 个 CAD 命令序列；
  - 每个模型附带多视图图像、点云、文本描述等多模态信息  
- mmABC：
  - 在 ABC 基础上构建 130 万+ B-Rep 模型 + 多视图图像 + 点云 + 文本；
  - 面向 B-Rep 生成与几何理解  

**如何用于几何 / 干涉 Agent 训练**

- 作为大规模几何先验：
  - 训练模型识别常见零件类型、几何构型；
- 结合 FreeCAD / PythonOCC 自动生成“是否干涉”的标签：
  - 随机组合两个 CAD 模型进行装配，控制平移 / 旋转，调用布尔交集获得干涉体积作为标签；
  - 构造 “给定两个布置方式（位置 A/B），哪个不会产生干涉？” 之类的训练样本。

---

### 5.4 Text-to-CadQuery 数据集（作为补充）

- **是否开源**：是（论文 + GitHub 项目）  
- **项目页**：https://github.com/Text-to-CadQuery/Text-to-CadQuery   

**数据内容**

- 在 DeepCAD + Text2CAD 上，补充 17 万条 CadQuery 注释；
- 每条样本包括：
  - 自然语言描述（含几何形状、尺寸、相对关系）
  - 对应的 CadQuery 代码（可直接在 CadQuery/FreeCAD 中执行生成模型）  

**如何为几何 / 干涉训练提供支持**

- 你可以：
  - 用 CadQuery 批量生成模型；
  - 再用 FreeCAD / OCCT 做“两个 CadQuery 生成零件之间的干涉采样”，自动生成训练样本和标签。

## 6. 若要评测 Agent：可用的开源 / 公开评测集

### 6.1 SGP-Bench – CAD Question Answering

- **是否开源**：是  
- **用途**：评测“几何理解 + 空间推理 + 符号程序理解”综合能力  

**评测方式**

- 输入：CAD 程序（或渲染图像） + 多选几何问题；
- 输出：一个选项（A/B/C/D），与标准答案对比；
- 指标：准确率（2D / 3D 分别统计）；
- CAD-Assistant 在 SGP-Bench 的 2D/3D 子集上给出了比较详尽的 baseline 和提升结果  

> 虽然这一基准没有直接给出“干涉”问题，但它对“几何理解”和“空间推理”的评测非常系统，是你评估 Agent 几何能力的首选。

---

### 6.2 CAD-Assistant 的 SGP-Bench 评测脚本

- **是否开源**：是（代码公开，非商业许可）  
- **内容**：
  - 仓库中 `sgp_bench_samples/` 目录内含 2D/3D FreeCAD `.FCStd` 测试文件，以及对应的题目；
  - `run_cad_evaluation.py` 实现了完整的评测流程（包括并行评测）。  

**你可以做什么**

- 替换其中的 Planner（如从 GPT-4o 换成你自己的模型 / 框架），保持工具链不变；
- 在相同基准上，直接比较几何 / 空间推理性能。

---

### 6.3 干涉检测的专门评测集（现状与建议）

- 目前没有发现类似 “ImageNet for collision/interference in CAD” 这样标准化、开源的干涉评测基准；
- 建议做法：
  1. **基于现有 CAD 数据集（如 Omni-CAD / mmABC / DeepCAD）合成装配对：**
     - 选两个零件，随机位姿布置；
     - 调用 FreeCAD / PythonOCC 做布尔交集，记录是否干涉；
     - 如有干涉，记录交集体积、接触区域等；
  2. **构造多选题 / 开放题形式的问题：**
     - “下列哪种布置不会产生干涉？”
     - “当前布置是否存在碰撞？如果有，请说明是否需要减小哪个零件的尺寸？”
  3. **用相同的几何核作为判定标准**，保证评测结果可重复。

## 7. 小结与落地建议

- 这一环节的“成熟度”，目前主要体现在：
  - **几何理解 / 问答评测（SGP-Bench + CAD-Assistant）** 已有较成熟的公开基准和代码；
  - **空间约束理解（SCOPE）** 处在论文阶段，但已经给出了系统的“空间三元组”数据设计，适合你借鉴；
  - **干涉 / 碰撞检测** 在工程软件层面（FreeCAD + OCCT）非常成熟，但在“LLM 基准”的层面尚无标准数据集，需要你自己构建。
- 若你想在“几何 / 干涉推理”这一 Link 上系统评估不同 LLM / Agent：
  1. 先用 **SGP-Bench + CAD-Assistant 框架** 评测「几何&空间问答」；
  2. 再在 FreeCAD + PythonOCC 上合成“装配 + 干涉”的数据与评测集；
  3. 若你愿意，也可以将这些合成数据做成公开 benchmark，在社区中占一个先手位置。
